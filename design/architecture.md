# Architecture

## 1. Purpose

Air Lab AI Data Copilot demonstrates a governed enterprise data copilot pattern. It serves teams evaluating how business glossary certification, semantic-layer boundaries, deterministic SQL, and an LLM narrative layer can be combined without allowing the model to control data access or policy enforcement.

## 2. Current System Shape

The repository combines architecture documentation, governance artifacts, sample data, semantic view definitions, evaluation material, and a local Python runtime. The local runtime is a reference implementation that runs against CSV-backed DuckDB views and a checked-in FAISS RAG index.

The project is not packaged with `pyproject.toml` or formal test tooling. Runtime commands are invoked with `python -m ...` from the repository root.

## 4. Runtime Flow

```text
User question
  -> glossary and dataset-register loading
  -> pre-inference refusal checks
  -> certified context retrieval from FAISS/store.json
  -> semantic view selection
  -> deterministic SQL template generation
  -> policy enforcement against the selected certified view
  -> DuckDB execution over local sample data via semantic SQL views
  -> local OpenAI-compatible LLM narrative generation
  -> governed response schema assembly
```

## 5. Data Flow

Governance inputs come from `01_governance/glossary.yaml` and `01_governance/dataset_register.yaml`. Semantic view descriptions and SQL files live under `02_semantic_layer/view_definitions/`. Local physical tables are CSV files in `03_data/sample_data/`.

`07_runtime_local/rag/build_index.py` embeds certified glossary and semantic-view documents into `07_runtime_local/rag/index.faiss` and writes document metadata to `07_runtime_local/rag/store.json`. At runtime, `retrieve_context.py` reads those files and returns certified context chunks.

`execute_query.py` registers the sample CSVs as DuckDB views, loads `vw_*.sql` semantic views, and executes deterministic SQL generated by `build_sql.py`. The LLM layer receives only the question, certified semantic context, and query results.

## 6. Configuration

Primary runtime configuration is in `07_runtime_local/config/runtime_config.yaml`.

Relevant runtime assumptions:

- RAG index path: `07_runtime_local/rag/index.faiss`
- RAG store path: `07_runtime_local/rag/store.json`
- sample data path: `03_data/sample_data`
- semantic SQL path: `02_semantic_layer/view_definitions`
- response schema path: `04_copilot_contract/response_schema.json`
- local LLM endpoint in `llm_generate.py`: `http://127.0.0.1:1234/v1`

Do not commit secrets. `.env` files are ignored by `.gitignore`.

## 7. Testing and SIT

There is no formal unit-test suite or CI configuration in the current repository. The practical SIT checks used for housekeeping were:

```bash
.venv/bin/python -m compileall -q 07_runtime_local
.venv/bin/python -m 07_runtime_local.ingest.load_glossary
.venv/bin/python -m 07_runtime_local.ingest.load_dataset_register
.venv/bin/python -m 07_runtime_local.copilot.refusal
.venv/bin/python -c "import importlib; b=importlib.import_module('07_runtime_local.query_engine.build_sql'); p=importlib.import_module('07_runtime_local.query_engine.enforce_policy'); e=importlib.import_module('07_runtime_local.query_engine.execute_query'); sql=b.build_sql('vw_active_customers','Show active customers by segment'); p.enforce_policy(sql,'vw_active_customers'); print(e.execute_query(sql))"
```

The full interactive copilot path also depends on a local OpenAI-compatible LLM server.

## 8. Deployment / Execution

The current execution target is local development from the repository root. In the documented enterprise target shape, local components map to managed services:

- FAISS index -> managed vector service;
- DuckDB/sample CSV execution -> Snowflake, Databricks, Fabric, or equivalent governed warehouse;
- Python orchestrator -> API service;
- local policy checks -> centralized policy engine;
- local response logging -> enterprise audit and observability stack.

## 9. Governance / Operational Notes

The project separates probabilistic reasoning from deterministic controls. The LLM does not generate SQL, enforce policy, access raw tables, or modify the response schema. Refusal checks use certified glossary and dataset register metadata before retrieval and query execution.

Operationally important gaps remain: no CI pipeline, no formal automated tests, no production secrets/configuration pattern, no persisted audit log, and no service boundary around the local runtime.
